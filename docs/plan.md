# 1인 프로젝트 개발 계획

목표: Gazebo 3D 컨베이어에서 취득한 물리 상태·카메라 영상을 MQTT로 연결하고,
설비 진단과 품질 검사를 함께 분석하는 CPU 시스템을 구현한다.

| 단계 | 작업 | 완료 판정 |
|---|---|---|
| 1 | Ubuntu 22.04 컨테이너·Gazebo·ROS2 구성 | 실제 카메라 영상과 모터 관측값 취득 |
| 2 | 도메인 랜덤화·자동 라벨·고장 주입 | 정상 센서 5,000개, 고장 2,000개, 영상 6,000개 |
| 3 | FFT·관리도·정상 학습 Autoencoder | 독립 테스트 F1 ≥ 0.80, 5회 CPU 측정 |
| 4 | YOLOv8n 파인튜닝·Grad-CAM·ONNX | 독립 시나리오 mAP50 ≥ 0.80, 100장 전처리 포함 측정 |
| 5 | TimescaleDB·품질 PostgreSQL·대시보드 | 2초 갱신·상관 그래프·검사 이력 |
| 6 | MQTT 안전 인터락·통합 검증 | 위험 판정 시 실제 Gazebo 모터 정지 |
| 7 | 실험 기록·실행 안내·GitHub 공개 | 깨끗한 클론에서 Compose 실행 가능 |

담당자는 hajijiha 한 명이다. 기획, 시뮬레이션, 데이터, ML, 서비스, 테스트,
문서화를 모듈별로 나누되 팀원이나 수행하지 않은 실험을 만들지 않는다.
선택 과제는 CPU 배포에 필요한 ONNX 변환·비교를 우선한다.
RUL은 필수 PHM 개념 설명과 실제 수명 예측 구현 여부를 구분한다.
