# 예지보전: 물리 특징, 정상 학습과 평가

## PHM 4단계

1. 취득: Gazebo 모터 관절의 실제 속도·위상을 읽고 가상 진동 센서 창을 생성한다.
2. 특징 추출: 시간·주파수 특징과 Hann FFT를 산출한다.
3. 진단: 통계 관리도와 정상 데이터만 학습한 Autoencoder를 비교한다.
4. 수명 예측: 진단 이력을 남기지만 **LSTM RUL 회귀는 구현하지 않았다**.
   고장 레벨과 실제 잔존수명 사이의 근거 있는 관계, run-to-failure 레이블,
   개체별 수명 분리 검증이 있어야 실제 수명 예측을 수행할 수 있다.

## 샘플링과 베어링 주파수

`fs = 2048 Hz`, 창 길이 `N = 2048`이므로 창은 1초이고 주파수 분해능은
`Δf = fs/N = 1 Hz`, Nyquist 한계는 1,024 Hz다.
회전 속도는 실제 Gazebo 관절 각속도를 `fr = abs(omega)/(2π)`로 변환한다.
회전 기본값은 약 25 Hz = 1,500 RPM이다.

베어링 볼 수 `n=8`, 볼 지름 `d=7.94 mm`, 피치 지름 `D=39 mm`, 접촉각 `θ=0`:

```text
BPFO = n/2 × fr × (1 - d/D × cos θ) ≈ 79.641 Hz
BPFI = n/2 × fr × (1 + d/D × cos θ) ≈ 120.359 Hz
```

BPFO는 외륜 결함 위치를 볼이 지나가는 횟수, BPFI는 내륜 결함 위치를
지나가는 횟수다. 1X/2X/3X 회전 성분, ball-pass 성분과 350 Hz 공진을
분석한다. 이러한 주요 분석 대역은 Nyquist 이하이나 이상적인 충격 함수의
무한 고조파를 실제 센서가 모두 측정한다고 가정하지 않는다.
Hann 창은 비정수 결함 주파수의 spectral leakage를 줄인다. 창 합으로
진폭을 보정하고 DC는 별도의 mean으로 유지한다. BPFO/BPFI 진폭은 중심
주파수 주변 ±2 FFT bin의 최대값을 사용한다.

## 특징과 알고리즘

시간 특징: mean, RMS, peak, crest factor, Pearson kurtosis(정규분포 기준 3).
주파수 특징: dominant frequency, spectral energy, BPFO amplitude, BPFI amplitude.
총 9개이며 mean을 제외한 양수 특징은 log1p로 변환한다.

관리도는 정상 훈련 집합의 평균·표준편차로 특징을 표준화하고,
RMS/peak/energy/BPFO/BPFI의 최대 절대 z-score를 사용한다.
여러 특징의 최대값을 사용하는 다변량 감시를 단순화한 관리도다.
임계값을 임의의 3σ로 단정하지 않고 검증 집합의 F1로 선택한다.
장점은 원인 특징을 설명하기 쉽고 계산량이 작다는 점, 한계는
정규성·운전 조건 변화에 민감하고 다중 비교에 대한 별도 교정이 없다는 점이다.

AE 구조는 `9 → 16 → 3 → 16 → 9`, ReLU, Adam(lr 0.003), 180 epoch,
batch 128이다. 학습에는 **정상 train 3,500개만** 사용한다.
표준화 평균·표준편차도 이 정상 훈련 집합으로만 맞춘다.
재구성 제곱 오차 평균을 이상 지표로 사용한다.
장점은 특징 사이 관계를 모델링한다는 점, 한계는 학습 분포 밖의 정상 운전도
이상으로 보거나 결함까지 잘 재구성해 놓칠 수 있다는 점이다.

고장 train 1,400개는 비교 시나리오 기록으로 보존하며 AE에 넣지 않는다.
검증 normal 750 + fault 300은 임계값과 HI scale을 선택하는 데 사용한다.
테스트 normal 750 + fault 300은 최종 평가에만 사용한다.
각 split은 별도 seed·노이즈 시나리오로 생성한다.
현재 물리 모터 운전 속도는 고정이므로 다양한 RPM에 대한 강건성은 증명하지 않는다.

## Anomaly Score와 HI

검증 집합의 레벨 0/3/6/9별 오차 중앙값과 최대 오차를 단조 증가 기준점으로
만든다. 이를 score `[0.05, 0.30, 0.55, 0.85, 1.0]`에 piecewise-linear
보간한다. 관리도 score와 AE score를 **각 0.5의 가중치**로 평균한다.

`HI = 100 × (1 - anomaly_score)`.
정상: HI ≥80, 주의: 60≤HI<80, 경고: 40≤HI<60, 위험: HI<40.
경계는 실수 HI에 적용하고 표시값을 반올림한다.
Anomaly Score는 [0,1]의 상대 열화 지표이며 보정된 고장 확률이 아니다.
검증 시 고장 라벨을 HI scale 교정에 사용하지만 **운영 추론은 진동 특징만**
사용한다. 운영 입력 fault_level로 HI를 계산하지 않는다.

## 실제 평가

아직 실행 결과가 없는 경우 표에 측정값을 작성하지 않는다.
`docs/results/pdm.json`을 근거로 최종 비교표를 갱신한다.

| 알고리즘 | Precision | Recall | F1 |
|---|---|---|---|
| 관리도 | 측정 대기 | 측정 대기 | 측정 대기 |
| 정상 학습 AE | 측정 대기 | 측정 대기 | 측정 대기 |

CPU 추론은 **FFT + 특징 추출 + 두 모델 score + HI** 전체를 포함한다.
100개 창 반복 평균을 한 회로 하여 5회 측정하고 원본 ms 값을 기록한다.
목표는 F1 ≥0.80, 평균 ≤100 ms다. 전송·DB 지연은 별도 통합 검증 대상이다.
훈련·검증·테스트 비율은 각 클래스 70/15/15이며 테스트 개수와 사용 Python,
PyTorch 버전, seed, 교정 임계값을 JSON에 남긴다.
