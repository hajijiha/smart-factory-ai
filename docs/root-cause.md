# 시뮬레이터의 원인 개입 실험

상관 그래프에 더해, 같은 조건에서 Fault_Level만0과5로 바꾸는60쌍의 개입 실험을 수행했다.
조명·배경·카메라·제품 위치, 물리 관절 baseline, 진동 RNG 및 결함 발생의 uniform draw를 쌍 안에서 공유한다.
쌍별 개입 순서는 무작위로 결정하고 Gazebo에서 실제 카메라 JPEG120장을 취득했다.
기준 PdM·YOLO 모델을 고정한 뒤 파형 진단과 결함 검출을 평가한다. 학습·모델 선택에 쓰지 않는다.

차이는 level5−level0이며 전체 쌍을 resample하는 bootstrap5,000회로95%구간을 계산했다.

| 측정 | 평균 차이 |95% bootstrap 구간 |
|---|---:|---|
| 진동 RMS |+.27124 |[.27070,.27176] |
| Health Index |−40.86 |[−42.34,−39.50] |
| 생성 불량률 |+.4167 |[.3000,.5333] |
| 모델 검출 불량률 |+.3333 |[.2167,.4500] |

[원본 결과와 쌍별 기록](results/completion-v3/root-cause.json)에 데이터·영상·고정 모델 해시를 포함한다.
센서·생성 불량·검출 불량의 증가 구간이0을 넘는다는 사전 성공 기준을 충족했다.

Fault_Level이 진동과 결함 확률을 함께 조절하도록 설계했으므로 이 결과는 시뮬레이터에 구현한 구조적 원인을 검증한다.
실제 공장의 물리 원인을 발견했거나 현실의 고장→불량 메커니즘을 증명한 결과는 아니다.
현실에 적용하려면 운전 조건·원료·시간 추세 등을 통제한 실설비 데이터와 별도 개입·인과 검증이 필요하다.
